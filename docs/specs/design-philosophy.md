# DataAgent 设计哲学

> **一句话（Canonical tagline）**
> **一切皆断言，判断皆有据。**
> *Everything is an assertion; every judgment is evidence-backed.*

> 状态：**长期稳定（跨版本）** ｜ 定位：项目的灵魂，代码、文档、版本迭代都由此出发并受其约束。

---

## 1. 为什么需要一份哲学

代码能被抄，哲学抄不走。Unix 的"一切皆文件"、Flink 的"一切皆流"、dbt 的"把分析工程化"，最强的都不是某段代码，而是那个一句话能说清、但别人复刻不来的世界观。

DataAgent 的差异化不是"多一种检测算法"——检测层是 30 年共识的"标准件"（Wang & Strong 15 维度，GE/Soda/Deequ 都映射到同一批）。我们的差异化是**围绕检测的 Agent 闭环（归因 + 整改 + 审批 + 评估）**，而这个闭环要成立、要经得起工程化拷打，必须有一条统一的世界观贯穿。

本文就是这条世界观。它是**规范**（代码 review 的否决依据），不是散文。

---

## 2. 核心命题

**一切皆断言，判断皆有据。**

拆成两句：

1. **一切皆断言**：整条质量链路——检测、归因、整改、评估——是**同一种东西**，不是四个独立模块。
2. **判断皆有据**：任何"有结论"的地方，结论必须**携带证据**；没有证据的结论不成立。

这两句对应三条公理。

---

## 3. 三条公理

### 公理一 · 断言统一（Uniformity of assertion）

一个**断言（Assertion）**是三部分的统一体：

| 部分 | 是什么 | 谁定义 |
|---|---|---|
| 声明 declaration | "什么算好"：表 / 列 / 条件 / 阈值，声明式 | 用户（自由表达） |
| 判定 verdict | pass / warn / fail | 框架 |
| 证据 evidence | 触发时：SQL + 命中行 + 期望 vs 实际 + 血缘 | 框架自动采集 |

L0 规则、L1 统计、L2 语义**不是三种东西，是同一种断言的三种判定方式**——只差"怎么算出 verdict"：

- L0 规则断言：确定性（唯一 / 引用 / 空值 / 值域）
- L1 统计断言：基线 + 偏离（freshness / volume / distribution）
- L2 语义断言：LLM 推理，但**必须落回证据**

由此自然推出纪律"能规则不统计、能统计不 LLM"——它不再是悬空的口号，而是"**先试最便宜的判定方式，判不了才升级**"。

### 公理二 · 证据一等（Evidence is first-class）

证据不是"异常旁边附的一段话"，而是一个**结构化对象**：`query + rows + expected-vs-actual + lineage/blast-radius`。

- 检测的证据：触发判定的 SQL + 命中行。
- 归因的证据：支撑"根因假设"的血缘 / 数据切片 / 相似案例。
- 整改的证据：提案所依据的根因 + 离线复检结果。

**没有证据的结论不成立。** 这一条是对 LLM 幻觉的护栏（cs2680 第 7 篇：错误是复合的，95% 单步正确 × 50 步只剩 8%），也是"更准""更稳"的根：归因 / 整改可以被 eval 检查"证据是否支撑结论"。

### 公理三 · 确定性优先（Determinism first）

能规则不统计，能统计不 LLM。LLM 是**昂贵的最后手段**，只在确定性判据判不了时才介入，且介入时：**输入是证据包，输出是带证据的结构化结论**，不给它裸奔数仓的工具。

这一条同时是"更省"（cs2680 第 1 篇：优化目标是 $/成功任务，不是 tokens/s；第 6 篇：LLM 是 15× token）和"更稳"（确定性可重放、可 CI 门禁）。

## 4. 由公理推出的工程原则

| # | 原则 | 从哪条公理来 | cs2680 支点 |
|---|---|---|---|
| P1 | **确定性可重放**：同快照 + 同断言 → 同结论 | 公理三 | 使 CI eval 门禁成立 |
| P2 | **只读护栏**：SELECT-only + 白名单 + 行上限；Agent 只提案、Harness 执行 | 公理三 | 第 2 篇：模型只提议、harness 执行 |
| P3 | **按需取证据**：adapter 暴露"能查到什么"，不预灌元数据 | 公理二 | 第 3 篇：上下文是租金 |
| P4 | **证据接地**：LLM 只对已抓到的证据做推理，不自由发挥 | 公理二 | 第 6 篇：工具设计=上下文设计 |
| P5 | **集中验证**：单一验证瓶颈，不搞独立 agent 裸奔 | 公理二 | 第 4 篇：错误放大 17.2× vs 4.4× |
| P6 | **幂等**：可安全重试，无双重副作用 | 公理三 | 第 6 篇：默认幂等 |
| P7 | **评估门禁**：成本归一的成功率 + pass^k（非 pass@k）+ holdout | 公理二 | 第 8 篇：别信成功率 |

## 5. 反例清单（什么算违反哲学）

代码 review 时，出现以下任一，即违反本哲学，应当否决或修正：

1. **裸结论**：一个不带 SQL / 命中行的"异常"或"根因"。
2. **裸奔数仓**：让 LLM 直接写并执行任意 SQL，绕过 SafeSQL 白名单 / 行上限。
3. **为多 agent 而多 agent**：没有"任务拆得开 + 省下的串行时间盖过协调税"的依据就拆 agent。
4. **全量预灌元数据**：把整库 schema / 血缘 / 术语一次性塞进上下文。
5. **未复检即宣称修复有效**：修复方案没经过"副本数仓应用 + 复检"就号称成功。
6. **记忆当 RAG**：只"换入"不"换出"、无出处无有效期的案例库，让过期事实压着新事实。

## 6. 映射到四个接缝

| 接缝 | 在哲学里是什么 |
|---|---|
| `WarehouseAdapter` | **取证据的接口**：暴露能力（execute/list/describe/row_count），按需拉取，不做元数据 dump |
| `Detector` | **断言**：声明 + 判定 + 证据 |
| `RemediationPolicy` | **整改断言**：根因 → 提案 + 风险 |
| `CaseStore / RAG` | **证据的持久化复用**：虚拟内存模型，带 provenance + valid-time（第 7 篇） |

## 7. 如何演进（版本化）

- **核心命题冻结**："一切皆断言，判断皆有据"像 Flink 的"一切皆流"一样，几十年不动。
- **公理可长**：允许在公理之上长出**子原则**，例如未来把"契约（schema contract）"纳入为第四种断言（断言统一扩展到生产者-消费者边界）。
- **原则可增删**：工程原则随实践迭代，但每增删一条都要在 CHANGELOG 里记录"为什么"。
- **反例清单随版本同步**：每发现一种新的违反方式，追加进 §5，让"壮大"有迹可循。
