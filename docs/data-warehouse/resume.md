# 简历 / 面试素材（数据开发方向）

> 项目：基于 Olist（巴西电商，~10 万订单）从零搭建企业级数仓，并用自研的 DQAgent 做数据质量运维监控。
> 定位诚实：**方法论正确、demo 规模**（DuckDB 引擎），对标 JD 的「分层/建模/指标/治理」硬技能，不虚标 Hadoop/实时海量调优。

## 一句话

从全量 Olist 原始数据搭建一套 **ODS→DWD→DIM→DWS→ADS 五层数仓**，沉淀**维度建模 + 指标体系 + 数据治理**，并用开源 Agent（DQAgent）实现「检测→归因→整改→审批」的数据质量闭环。

## 核心工作（可量化）

**① 数仓建设（分层 + 建模）**
- 设计并落地 5 层架构：9 张 ODS 原始表 → DWD 类型规范化（`TRY_CAST` 脏值容错）→ 6 张 DIM 维度表（主键唯一 + geolocation 一邮编一行去重）→ 4 张 DWS 汇总表 → 3 张 ADS 宽表/看板。
- 星型模型：4 张事实表（订单/明细/支付/评价）+ 6 张维度表（日期/客户/卖家/商品/地理/品类）；`ads_order_wide` 宽表 JOIN 维度**零膨胀**（行数 = 明细数）。
- 幂等建仓（`CREATE OR REPLACE`）+ `clone_warehouse` 一次性副本，评测不污染干净数仓。

**② 指标体系（口径沉淀）**
- 定义 4 个原子指标（GMV/订单量/支付额/评价分）+ 4 个派生指标（客单价/复购率/履约时效/支付转化率），每条写清定义/计算逻辑/时间与去重口径（如 GMV 含取消、复购按 `customer_unique_id`）。

**③ 数据治理（声明式质量规则）**
- 25 条 YAML 声明式断言（`unique`/`not_null`/`null_rate`/`value_range`/`referential`），覆盖主键唯一、星型 FK 参照、值域、空值、跨表一致性（金额对账/状态矛盾/邮编一致）。
- 关键设计：维度表主键唯一断言拦截「JOIN 膨胀」的**根因**（维度表重复主键 → 事实×维度行数翻倍）。

**④ Agent 数据质量闭环（DQAgent）**
- 注入 5 类真实故障（主键重复/维度键重复/孤儿/空值/负值）→ 确定性检测**秒级全检出**（检测 F1 = 1.0，263 个测试 CI 门禁）。
- `run` 全流程：L0 规则 → L1 统计 → L2 语义 → 薄归因（证据包 + 单次 LLM）→ 整改（风险分级）→ HITL 审批门禁（高危只提案不执行）。

## 面试可讲的技术点

1. **分层职责分离**：ODS 保留脏数据作证据，DWD `TRY_CAST` 把脏值→NULL（加载层健壮），检测层严格抓脏值——「加载容错、检测严格」。
2. **geolocation 去重口径**：一邮编多城市 → 取众数城市，消除 zip→多城市矛盾（`dim_geolocation` 一邮编一行）。
3. **JOIN 膨胀检测**：维度表主键唯一是膨胀的根因拦截；膨胀率检测本身是 roadmap 后置项（不混淆根因与后果）。
4. **幂等 + 可复现**：建仓 `CREATE OR REPLACE`；评测用 `clone_warehouse`（DuckDB EXPORT/IMPORT）隔离注入。
5. **Agent 只提案不执行**：`WarehouseAdapter` 只有 4 个只读原语，接口层就没有写能力，高危整改走 HITL。
